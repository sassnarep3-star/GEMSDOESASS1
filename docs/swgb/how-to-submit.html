How to submit to the DOE GEMS Prize Challenge

GEMSDOESASS1 · DOE GEMS Prize Challenge (DrivenData #306) · generated from evidence/*.json · 20261027T122104Z

Exactly how to make a submission

  1. Download the file: ⬇ gemsass1-swgb-hrv2-44090dots-20261027T122104Z-f9b3f764-zeros.tif (or the .zip, which contains the same single GeoTIFF — both are accepted).
  2. Log in to DrivenData and open the competition's submission page: https://www.drivendata.org/competitions/306/competition-doe-gems/submissions/ → New submission.
  3. File to submit: choose the downloaded .tif (single band, float32, EPSG:32611, 3730 × 3292 px, 100 m, geotransform (100, 0, 243350, 0, −100, 4508550) — identical to the organizer template; values 0.0/1.0; no NaN).
  4. Note (optional) — paste this so the team can tell submissions apart later:
    GEMSASS1 SWGB: 5x segment-withheld HGB on lidar+GeoDAWN, 44090 dots 2.8px, >600m off-catalogue; HOLDOUT-DTI 0.140 vs base 0.101
  5. Submit. Copy the score shown on the submission page into registry/organizer_confirmed.json (name, sha256 f98c20df5bc67a48…, score, UTC time). Only then may the number be written as ORGANIZER-CONFIRMED anywhere in this project.
  6. Weekly cap: whatever the submission page displays (DrivenData staff, forum 11553). Do not spend a slot on a file whose verdict is not promote.

Why earlier downloads failed with "Predicted values must be in range [0, 1]"

That message is raised when any pixel is outside [0, 1] — NaN and ±Inf included on some validators. This project's writer (src/gems/submission.py) clips to [0, 1], writes zeros outside the footprint, forbids NaN/Inf anywhere, and refuses to write a file that fails any check; the receipt is published next to the file (checks.json).
