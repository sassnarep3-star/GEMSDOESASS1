## External data availability

Candidate one and candidates three/four can be formulated from the competition-provided layers and official DEM links, so they do not inherently require additional third-party data. Candidate two needs radiometric source products if those bands are not present in the provided feature file. The official source is the [USGS GeoDAWN data release](https://doi.org/10.5066/P93LGLVQ), with its [USGS description and public product inventory](https://www.usgs.gov/data/geodawn-airborne-magnetic-and-radiometric-surveys-northwestern-great-basin-nevada-and). That page was reachable during this review and describes deliverable radiometric grids, but **actual direct file retrieval, footprint equivalence, licensing compatibility, and grid alignment were not tested here**. The USGS page identifies CC0 rights. The candidate is therefore source-plausible but not data-ready. Do not substitute raw GeoDAWN grids for the official competition-aligned bands without an auditable reprojection/coverage validation.

## Required top-candidate validation before any TIFF

1. Check the assigned method paragraph and registry. If candidate one is outside the allowed lane or exceeds surface novelty thresholds pre-placement, log duplicate/stop before placing detections.
2. Verify exact competition-stack source/version and `sample_submission.tif`; inspect channel names, units, nodata, transform, EPSG, dimensions, and footprint. No local artifacts are present currently.
3. Freeze segment groups and buffer; in each fold, derive all catalogue-dependent variables only from visible segments and mask visible labels pixel-exactly. Recompute each fold's catalogue features from fold-visible geometry—never use cached full-catalogue derivatives without proof they are fold-safe.
4. Run a feature-alone leakage canary for every raw and derived feature, with `AUC > 0.90` treated as leakage until demonstrated otherwise.
5. Compare against the same-evaluator incumbent using pooled DTI at alpha 0.2, beta 0.8, 300 m triangular kernel; save evaluator version, withheld-positive count, fold scores, paired 95% CI, bootstrap draws/seed, and the exact candidate config. Report only as `HOLDOUT-DTI` with all required metadata.
6. Check rank correlation against every registry raster on the continuous surface before selection; stop if absolute rho exceeds 0.90. After writing, compare final dots against the same registry and stop if more than 70% are within 3 pixels of any single registry raster. Preserve exact comparison direction and denominator.
7. If and only if the preregistered holdout wins with a paired 95% CI above zero and all scientific/novelty gates pass, call the shared writer. Reopen the bytes and validate float32, one band, EPSG:32611, exact grid transform/shape, nodata outside the footprint, and [0,1] values. Save SHA-256 and validator JSON.
8. The selector must separately verify the live weekly slot cap. Evidence promotion is not slot selection. Do not upload from this document.
